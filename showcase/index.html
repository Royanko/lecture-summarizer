Why I built it

A recording is not study material.

I study at Ben-Gurion University. My math courses are recorded, but a two-hour video is slow to search, and ordinary transcription misses the Hebrew and the formulas on the board. So I built a tool that handles both, and used it all semester.

Architecture

Two servers, one pipeline, plain files.

The interface and the processing are separate programs that talk over a small REST API. A lecture runs as a background job, so the interface stays responsive during an hour of work.

Frontend · port 3000

Next.js 15 + React

TypeScript. Upload, live progress, card renderer, KaTeX math, tutor chat. State is kept in the browser session, so a refresh resumes polling.

⇄
Backend · port 8000

FastAPI (Python)

14 REST endpoints. Each lecture is a background job with a job ID. Owns timeouts, retries, checkpoints and file output.

⇄
Media tool

ffmpeg

Splits recordings into segments, extracts one frame per minute.

AI model

Google Gemini API

One client for transcription, summaries and chat. Large media goes through the Files API.

Storage

Local files

Summaries and transcripts per course, plus a checkpoint folder per unfinished job.

upload→split (ffmpeg)→transcribe + frames→checkpoint→summarise→repair tags + LaTeX→master summary→save
Polling, not a live socketThe browser asks for job status every 2.5 seconds. It is simpler than WebSockets and survives a page refresh or a dropped connection.
Progressive resultsThe job publishes each segment as it finishes. The summary page opens after the first one, long before the lecture is done.
Stateless chatEvery tutor request carries the summary and the chat history. The server rebuilds the conversation each time and stores nothing.
Uploads bypass the proxySmall JSON calls go through the Next.js proxy. Video files go straight to FastAPI, because the proxy cuts requests off at 10 MB.
Prompts live in filesEach AI task has its own prompt file. Changing the summary format means editing text, not code.
Files before a databaseOne user and text output: folders per course are easy to inspect and back up. A database is the next step if there are more users.

A hard timeout around every AI call

The AI library sets no default timeout, so one stuck request could freeze a job forever. Every call runs in a thread pool with a deadline.

def _timed(label, fn, *args, timeout, **kwargs):
    future = _gemini_pool.submit(fn, *args, **kwargs)
    try:
        return future.result(timeout=timeout)
    except concurrent.futures.TimeoutError:
        raise TimeoutError(
            f"'{label}' timed out after {timeout}s")

Polling that stops itself

The frontend checks the job on a timer, ignores a failed check, and stops when the job reaches a final state.

async function tick() {
  if (!running) return;
  try {
    const res = await fetch(proxyUrl(`/jobs/${jobId}`));
    if (res.ok) {
      const job = await res.json();
      onUpdate(job);
      if (job.status === "done" ||
          job.status === "error") return;
    }
  } catch { /* transient error: retry */ }
  setTimeout(tick, intervalMs);
}

Engineering challenges

What broke, and how I fixed it.

Problem

Jobs died halfway

One network error near the end of a two-hour lecture meant starting from zero.

Solution

Checkpoints and resume

Each segment is written to disk when it finishes. A resumed job loads those files and continues with the next segment.

Problem

Rate limits and calls that hung

The AI service rejected requests over quota, and some calls never returned at all.

Solution

Timeouts and exponential backoff

Every call has a deadline. Quota errors wait 2 minutes, then 4, 8, up to 30, or the delay the server asks for.

Problem

Hebrew and math fought each other

Right-to-left text mixed with LaTeX produced broken formulas and stray grey code blocks.

Solution

Fix the prompt, normalise in code

A stricter prompt, a normalising step for what slips through, and one fewer AI call per segment.

Problem

Recordings too big to upload

Videos are hundreds of megabytes; the frontend proxy stops at 10 MB.

Solution

Direct upload, then split

The browser sends the file straight to the backend, and ffmpeg cuts it into segments the AI service accepts.

Problem

The AI provider changed twice

I moved to Google's Vertex AI, later closed that account, and my model versions were retired.

Solution

One swappable AI client

All AI calls go through a single client, so switching provider changed the connection code, not the pipeline.

Built with an AI coding assistant, and what it taught me

I built this project with Claude Code. I defined what the product should do, chose between the options at each step, tested every change on my own lectures, and decided what to keep. The assistant wrote most of the code under that direction.

Building it taught me a lot:

  • Coding. Reading code, following its logic and finding where a bug comes from.
  • Working with AI models. What they do well, where they fail, and how to check their output.
  • Web servers and APIs. How a request travels from the browser to a server and back.
  • How the frontend works. Pages, components, state and styling.
  • How the backend works. Endpoints, background jobs and saving files.
  • Styling. Layout, colour and right-to-left text.
  • Git and GitHub. Commits, branches and keeping secrets out of the repository.
  • Writing better prompts. Precise requirements give better results.
  • Adjusting my workflow. Small steps, with a check after each one.
  • Tokens. How usage is counted, and how to spend it carefully.
  • Skills, connectors and plugins. Extending the assistant with reusable instructions and outside tools.

What I took from it

  1. Plan for failure first. Timeouts, retries and checkpoints mattered more than any feature.
  2. AI output is input. It has to be checked and repaired like any outside data.
  3. Test on the real thing. A short clip hid what a two-hour lecture exposed.

What I would improve next

  • Automated tests in place of manual end-to-end checks.
  • Hosting and accounts, so classmates could use it.
  • A database once there is more than one user.
  • Parallel segments within the rate limits.
